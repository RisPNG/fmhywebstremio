# FMHY's Website Streamer Addon for Stremio

Stremio Addon that serves video HTTP URLs from streaming websites listed by [FMHY](https://github.com/fmhy/FMHY/wiki/Streaming).

The addon keeps FMHY directory synchronization outside user requests. Maintenance jobs ingest the official video directory and non-English streaming sections into a last-known-good local registry, classify candidates against bounded source-family fingerprints, run positive and negative health corpora, and record source-to-provider dependency edges. Both directory documents must load and parse before the combined snapshot replaces the previous one. The runtime uses only sources with a successful validated extractability outcome and returns validated partial results within a hard deadline.

Requests consider every enabled, healthy source within the discovery deadline, with bounded concurrent lookups. The overall deadline is 30 seconds, with at most two active network requests per host. Stream validation rotates across sources before trying their additional variants and continues through all discovered candidates within the overall deadline. HLS validation checks the selected video and audio renditions, including their keys, initialization data, and sampled segments, within those shared network limits. Media responses that declare HLS or DASH use their protocol inspectors even when their URLs have no file extension. The signed HLS relay gives playlists, segments, initialization data, and keys filenames and media types that match their role, so strict players can follow streams whose upstream paths hide their formats. Rewritten playlists report their new byte length, while media requests retain native byte ranges. Parallelism controls active requests, not the number of candidates checked or streams returned; failed variants do not consume a fixed result quota. Repeated stream identities within a source are deduplicated; matching codec and resolution profiles do not merge distinct URLs or languages.

The extraction engine is organized around small tagged contracts:

```text
Stremio request
    -> source family
    -> resolver-owned host delegation
    -> HLS / DASH / direct-media inspection
    -> deterministic selection and deduplication
    -> Stremio response
```

Runtime sources come from the freshly audited FMHY registry. Every one-shot audit also generates the committed deployment registry, so the same passed sources are available on stateless hosts after the audit changes are committed. New integrations belong in focused source-family or host-extractor modules rather than route handlers. Sites absent from the current FMHY list or without fresh stream validation are not shipped.

IMDb requests use Cinemeta to find the TMDB ID. When a TMDB access token is configured, IMDb and direct TMDB requests use the same canonical TMDB metadata before source matching. This keeps alternate Cinemeta titles from hiding a title that the source already carries. Without a token, IMDb requests retain Cinemeta metadata and direct TMDB requests retain their ID-only identity.

Canonical episode numbers and titles from Cinemeta remain part of the resolved series identity. Collection-based sources can use the first episode title for discovery and check the known seasons without making another metadata request.

## Development

Use the repository's mise-managed toolchain:

```sh
mise exec -- npm ci
mise exec -- npm run ci
mise exec -- npm run build
```

`npm run verify:contracts`, `npm run verify:diagnostics`, and `npm run verify:registry` provide focused architectural regression checks. The generated matcher registry is committed and verified in CI.

## Live extractability report

Run the opt-in live audit separately from deterministic CI tests:

```sh
mise exec -- npm run test:extractability
```

The audit fetches the FMHY video and non-English directories, freshly contacts every normalized streaming entry, recognizes supported site families, and tests known positive and negative media cases through discovery, extraction, and fresh stream validation. Its JSON report preserves FMHY names, source IDs, domains, aliases, sections, tags, stage outcomes, and typed failures in `.data/extractability/report.json`, while runtime eligibility and health history are saved to `.data/extractability/sources.json`. Sources absent from the current directory are removed from the maintenance registry and health history. Passed sources are also written to `src/engine/registry/deployment-registry.generated.ts` for stateless deployment.

Recognition checks an entry's declared alternate domains when the current domain does not match an implemented family, within one request, byte, and time budget. The matching listed domain becomes the source's active domain while its FMHY identity stays intact. Directory refreshes retain that choice while it remains listed. Removing the active domain clears its recognition and health so the remaining domains must qualify again, while an administrative disabled status remains in force.

Provider dependency edges are saved to `.data/extractability/dependencies.json`. The report includes root-cause groups that connect a typed provider or protocol failure to every affected source.

An individual site failure is a report result rather than a test-process failure. The command exits successfully when at least one site produces a freshly validated stream and exits unsuccessfully when no site does. `extractable` and `degraded` report entries are runtime-eligible only when they contain at least one validated positive result. Recognition-only, discovery-only, failed, redirected, unreachable, blocked, inconclusive, unknown, unsupported, disabled, and untested entries are not exposed by the runtime.

The report keeps site disposition separate from extractability. `redirected` records include the observed final URL when a candidate resolves to an unrelated domain. `unreachable` records include timeout, DNS, connection, TLS, or equivalent probe failures. `blocked` distinguishes access denial or rate limiting from a site that appears down. `inconclusive` covers ambiguous recognition or an exhausted probe budget, while `unsupported` means the site responded successfully but did not match an implemented source family. Tested family cases retain their discovery, extraction, validation, and typed failure details.

The server loads the committed deployment registry and freshly validates its eligible sources during production startup. Each health case has a 30-second deadline and stops after one stream passes protocol validation. Persisted source health cannot override the shipped set or re-enable a source rejected at startup. Dependency edges reload every minute by default; `EXTRACTABILITY_RELOAD_INTERVAL_MS=0` disables that reload. Every production-healthy FMHY site is added to the configure page. The enabled or disabled value is encoded into that configured add-on URL and filters runtime source selection. The audit currently recognizes only source families implemented by this repository, so broad directory reporting does not imply broad extraction support.

Startup HTTP failure summaries include request and response URL hashes, the media request context hash, response body fingerprints and capture lengths, redirect hosts, status, content type, and selected CDN headers. Runtime metadata identifies Node, Undici, and the platform. These fields allow local and deployment-network failures to be compared without publishing media URLs, request credentials, or response bodies.

The implemented reusable families include ArrowTV, BiliBili, CinemaOS, Cinetaro, 67Movies, KKPhim, MilkBox, MovieNerds, PressPlayX, P-Stream-compatible frontends, and Dooplay sites. CinemaOS uses exact TMDB-backed catalog pages and the Speedracelight architecture exposed through its configured Videasy player. 67Movies follows its configured Vidlove and Cinezo players while keeping its own exact search matching. CineGo remains unavailable because its declared player requires an unsupported grant architecture. P-Stream sites remain non-eligible when the provider architecture cannot find the known health-corpus media from the deployment network. Dooplay sites remain non-eligible when search discovery is incomplete or delegated players fail fresh validation. Browser-only anti-bot challenges, authenticated sites, client applications without a server-reproducible playback contract, and hosts that return expired media remain typed blocked, unsupported, failed, or inconclusive results rather than passes.

BiliBili uses the international site's public video collections. Discovery searches the series title and canonical first episode title, then requires an exact collection title, year, and requested episode number. A collection without a season label is accepted only when canonical episode metadata identifies one regular season matching the request. The selected video's returned archive ID and title must match the collection before its native player is queried for anonymous muxed MP4 resources. Playback and seeking use the existing signed relay with the native referrer. The family supports episode collections, and its health corpus covers Kisah Bawah Tanah episodes 1, 2, and 26, plus a nonexistent series.

Movies To Watch uses the reusable TMDB embed catalog family. Discovery reads the frontend's current public catalog configuration, follows its exact title/type/ID search and movie-year matching, and checks series season and episode availability against the same catalog used by its player UI. Its explicitly configured Videasy provider reuses the Speedracelight host architecture. The health corpus covers Inception (2010), Breaking Bad S01E01, Breaking Bad S05E16, and a deterministic nonexistent title. Later-season matching does not confuse the series premiere year with the requested season's release year.

BingeBang uses the reusable BingeBang player family on its current FMHY-listed domain. Discovery matches its own multi-search catalogue on exact title, media type, movie year, and available season count, then asks the player architecture for the exact requested season and episode. The site answers a missing episode with a missing player page. The player architecture reads the ticket issued by the play page, decrypts the counter-keystream envelope returned by its source list and resolver, and publishes the resolved servers. Referrer-bound streams use the existing signed relay, including HEAD requests and byte ranges for progressive MP4 playback and seeking. BingeBang is excluded from deployment because its current FMHY-listed domain returns Cloudflare HTTP 403 for search requests from the hosting network. The health corpus retains Inception (2010), Breaking Bad S01E01, The Boys S02E01, and a deterministic nonexistent title, and adds Kahar: Kapla High Council, Kudrat 1968: High Council S01E01, and Project: High Council S01E01 and S01E10. A later season released after the series premiere year stays matchable, while a missing episode remains absent.

AniCine uses its reusable catalog family and the supported players declared by its watch application. Discovery searches the site's TMDB catalog, checks movie titles and years or exact series seasons and episodes, then reads the current primary and alternative player URLs from the watch application's assets. Its Xpass player declares a ticketed data route, loader, and current playback build. The Xpass host reads that configuration without executing remote scripts, authenticates and decodes the data response, and follows the player's native server playlists. Its VidBolt option declares the requested media identity, resolver, and playback servers in its embed page. That host follows each declared server's native selector and preserves its HLS and MP4 alternatives, so fresh validation can discard unavailable language or quality variants while keeping working streams. Available streams from either configured player remain usable when the other player fails. Candidates and subtitle tracks enter the existing validation and signed relay with the player's declared referrer policy. Earlier CinePro players remain supported through their own configured token API. Subtitle metadata follows the canonical stream pipeline into Stremio. The health corpus includes Inception, Breaking Bad, The Boys season 2, Attack on Titan seasons 1 and 2, and a deterministic absent title. Anime uses the site's TMDB television catalog with Stremio season/episode numbering; AniList-only IDs and separate sub/dub selection are not introduced by this family.

SoapGo uses the reusable Soaper catalog family. Discovery searches its movie and television result sections, matches exact titles and movie years, and follows the requested episode from the series catalog. It reads the actual embedded player's configuration and checks the TMDB ID, media type, season, and episode before using the player's explicit VidsrcMe fallback through the existing host architecture and signed HLS relay. The Turnstile-protected resolver is not required for that fallback. SoapGo is excluded from deployment while its configured player is unreachable. The health corpus covers Inception (2010), Breaking Bad S01E01, The Boys S02E01, and a deterministic nonexistent title.

7Movies uses the reusable Cinrift catalog family and the Vidrift host architecture. Discovery matches its own search on TMDB ID, exact title, media type, and movie year, then checks the requested episode in the site's season catalog without comparing the series premiere year. It reads the configured player from the watch application's assets, requests the site's playback grant, and starts the player's session with the watch page as its parent. The source request uses that session's playback token and the player's default provider selection for the exact requested season and episode. Vidrift's signed playlists carry segment paths that strict HLS clients reject, so their streams declare relayed delivery and reach viewers through the existing signed HLS relay with playlist and TS suffixes. 7Movies is excluded from deployment while its search requests receive a Cloudflare challenge from the hosting network. The health corpus covers Inception (2010), Breaking Bad S01E01, The Boys S02E01, and a deterministic nonexistent title.

67Movies uses its semantic search to match exact TMDB IDs, titles, media types, and movie years. Its watch application declares the Vidlove and Cinezo players and the season lookup used to check the requested episode. Discovery follows those configured players and keeps the available streams. The Vidlove host reads its current API and startup providers, while the Cinezo host reads its declared Jennifer endpoint and follows the player's selection of original media, HLS, or remuxed media. Both hosts check the returned movie or episode identity before fresh validation. Referrer-bound media reaches viewers through the existing signed relay, which preserves HEAD requests and byte ranges for MP4 playback and seeking. Its response deadline covers connection establishment, while active media transfers continue until completion or client disconnection. The health corpus covers Inception (2010), Breaking Bad S01E01, Breaking Bad S05E16, and a deterministic nonexistent title.

MovieNerds uses its own stream API rather than a third-party player. Discovery reads the API origin and client headers declared by the site's application, requests the exact TMDB ID, media type, season, and episode, and accepts the response only when its title, movie year, season, and episode match the request. The API answers an unknown ID with unrelated catalogue data, so a mismatched identity counts as absent rather than as a playable result. Every direct HLS source it returns goes to fresh validation together with its subtitle tracks, while embed-only sources are not published. Its playlists come either from the site's own media proxy or from public CDNs, so viewers receive them directly without the signed relay. The health corpus covers Inception (2010), Breaking Bad S01E01, Breaking Bad S05E16, and a deterministic nonexistent title.

PressPlayX searches its own catalogue and follows only results whose title and media type match exactly. Its watch page embeds the VidSpark player for the requested movie or episode, and discovery continues only when that player's TMDB ID, season, and episode match the request. The VidSpark host reads the player key, server list, and fallback player declared by each player's application, then asks the player's own API for the requested media in the player's server order, stopping at the first server that answers. The source's first player falls back to the VidSpark CDN player when it has no stream or the stream does not play, so the host discovers both players and lets fresh validation drop a candidate that does not play. Every response must match the requested TMDB ID, media type, movie year, season, and episode. When a media proxy URL declares its upstream playlist and the request headers that upstream expects, the host requests that upstream directly with those headers, because the proxy itself often answers with temporary errors. All candidates reach viewers through the existing signed relay with the headers they require. The health corpus covers Inception (2010), Breaking Bad S01E01, Breaking Bad S05E16, and a deterministic nonexistent title.

ArrowTV lists its mirrors in the FMHY entry, and discovery follows them in order: a mirror whose search, watch page, or player is unreachable from the deployment network is skipped in favor of the next mirror. The catalog search matches exact TMDB IDs, titles, media types, and movie years, and series requests check the requested season and episode against the same TMDB season catalog the site's episode browser reads, using the read token its watch application declares. The watch page names its default player, and playback continues through its configured Cinezo or Vidlove host architecture. The host checks the returned movie or episode identity, follows the player's stream selection, and serves its referrer-bound media through the existing signed relay. The health corpus covers Inception (2010), Breaking Bad S01E01, Breaking Bad S05E16, and a deterministic nonexistent title.

MilkBox reads its current application asset, catalog proxy, and selectable VidSpark player from its own frontend. Discovery matches exact TMDB IDs, titles, media types, and movie years, then checks the requested season and episode against its catalog before opening the configured player. The existing VidSpark host verifies the returned media identity and follows each declared proxy's upstream playlist and request headers. Streams receive fresh protocol validation and reach viewers through the existing signed relay. The health corpus covers Inception (2010), Breaking Bad S01E01, Breaking Bad S05E16, and a deterministic nonexistent title.

KKPhim is listed in FMHY's Vietnamese streaming section and uses its documented PhimAPI lookup by TMDB ID and media type. Discovery checks the returned TMDB identity and declared season before selecting the exact native episode number from each available server. Translated catalogue titles do not replace that identity check, and an episode from a different season is not reused. Declared HLS streams enter the existing validation and signed relay, retaining the Origin and Referer of each API-declared embedded player. A Vietsub server label describes Vietnamese subtitles and does not imply Vietnamese audio. KKPhim is excluded from deployment because its media hosts return HTTP 404 from the deployment network, including with the native player headers. The health corpus covers Lightyear (2022), Kisah Bawah Tanah S01E01, S01E02, S01E26, and a deterministic nonexistent title.

Run continuous maintenance with:

```sh
mise exec -- npm run maintain:extractability
```

Watch mode runs immediately and then every six hours. `EXTRACTABILITY_INTERVAL_MS` controls the maintenance interval, while `EXTRACTABILITY_REPROBE_INTERVAL_MS` controls how soon a previously classified candidate is eligible for a fresh family probe. The default candidate reprobe interval is 24 hours. A one-shot audit retains the requested aggregate exit rule; watch mode remains alive and reports each run even when a run has zero extractable sites.
